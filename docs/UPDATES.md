# GitHub Releases 更新

更新來源為公開儲存庫 [i0nchu/chuh0o](https://github.com/i0nchu/chuh0o/releases)。
v0.1.0 已整合更新選單及獨立更新工具，使用完整 Windows 發布檔即可更新。

## 使用流程

1. 右鍵兔兔或系統匣，選「檢查更新」。僅在點選時連線，不會在啟動或背景定期檢查。
2. 選單保持開啟，背景取得 GitHub 最新正式版資訊。
3. 有較新且可下載的 Windows 版本時，文字變成「更新」；相同或更舊時為「已為最新版本」。
4. 點「更新」後，背景下載完整 ZIP，再自動關閉桌寵、替換程式並重新啟動，不顯示更新內容。
5. 關閉後重新打開選單會恢復「檢查更新」。下載或安裝已開始時則繼續顯示進度，避免重複執行。

儲存庫尚未有 Release 時顯示「尚無發布版本」。連線失敗、下載檔缺少或內容損壞時會顯示失敗並允許重試，
不會誤稱已為最新版本。原始碼預覽可查版本，點「更新」會提示「請使用發布版更新」，不替換開發檔案。

「隱藏兔兔」已簡化為「隱藏」。選擇動作僅在原始碼以 `--dev-actions` 啟動時顯示；
發布版即使帶入此參數也不會顯示，兔兔仍保留自主的走路、跳躍、打招呼與側躺。

## 發布檔案規則

使用 GitHub 正式 Release，tag 為 `vX.Y.Z`，例如 `v0.2.0`。
應用程式的 `src/chuh0o/__init__.py`、`pyproject.toml` 版本與 Release tag 必須一致。
只採用正式版本，不更新至 draft 或 prerelease，並以數字比較版本。

Release 需附上名稱完全相符的 `chuh0o-vX.Y.Z-windows-x64.zip`。
未來執行 `scripts/build.ps1` 時，會依程式版本自動命名。ZIP 為完整資料夾：

```text
chuh0o/
  chuh0o.exe
  _internal/
    assets/manifest.json
    PySide6/...
    resources/apply_update.ps1
    ...其他執行環境與素材
```

也接受沒有最外層 `chuh0o/` 的 ZIP。不可僅提供 EXE；Qt、程式及素材必須一起更新。
首個支援此功能的版本仍需讓朋友手動解壓縮並執行，之後才能透過選單升級。
程式資料夾及其上層必須可由目前使用者寫入，例如使用者自己的應用程式資料夾；不自動要求系統管理員權限。

## 替換與失敗復原

下載使用 HTTPS，限制大小，檢查下載長度；GitHub 若提供 SHA-256 digest 也會驗證。
ZIP 路徑、重複檔名、連結及必要執行檔會在解壓縮時檢查。不要求購買程式碼簽章憑證。
SHA-256 是完整性檢查，更新來源仍以此 GitHub 儲存庫及 HTTPS 為信任依據。

下載及解壓縮完成後，先檢查目標資料夾，再啟動隱藏的獨立 PowerShell 工具。
工具將新版複製到程式旁的暫存資料夾，等待舊程序退出，把舊程式移至備份，再切換新版。
新程序回報啟動成功及版本吻合後才刪除備份；替換或啟動失敗會嘗試還原並啟動舊版。
不會替換 Git 原始碼目錄，使用者設定必須存放在程式資料夾以外。

預設設定與記錄仍位於 `%LOCALAPPDATA%\chuh0o`，更新不清除偏好。
更新快取及每次作業的 `result.json` 位於該目錄的 `updates/<作業識別碼>/`。
成功時清除下載包及解壓縮內容；失敗時保留作業資料方便排查。

## 驗證範圍

自動測試涵蓋版本比較、選單顯示與重新開啟重設、連線失敗、下載損壞、路徑保護、
完整資料夾替換及啟動失敗後復原。Windows 工具測試使用暫存資料夾進行實際複製與移動，
以測試替身取代程序啟動與健康回報。
首版亦以實際打包 EXE 在隔離目錄驗證同版本套件替換、重啟、啟動回報、設定保留及快取清理。
第一個版本可確認線上版本查詢；跨版本線上升級需待後續版本發布後驗收。

GitHub 介面：[Releases API](https://docs.github.com/en/rest/releases/releases)。
